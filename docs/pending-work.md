# Lexorma — 미완료 작업 및 후속 개선

## 1. 문서 개요

- **목적** : 앞으로 구현하거나 검증·결정해야 할 일을 한 문서에서 관리한다. 이미 끝난 범위는 [completed-work.md](completed-work.md) 에 있다.
- **관리 원칙**
  - 다음 작업은 **사용자와 협의해 정한다.** 이 문서의 순서·우선순위는 후보 목록이며, AI 가 여기서 임의로 다음 작업을 골라 시작하지 않는다.
  - 작업 ID 는 기존 로드맵의 것을 그대로 쓴다(`M-n`, `AI-n`, `SEC-1`, `D-nn`, `U-nn`). 한 작업의 남은 범위가 여럿이면 원래 ID 아래에 둔다. 로드맵에 없던 항목만 새 ID(`UI-`, `AUTH-`, `PRJ-`, `COL-`, `AI-MCP` — `AI-MCP` 는 AI 로드맵 단계 번호가 아니다)를 붙인다.
  - 우선순위는 기존 로드맵·기록에 있던 값을 유지한다. 기록에 우선순위가 없던 항목은 **(임시)** 로 표시했다 — 착수 전에 사용자와 확정한다.
  - 완료되면 completed-work.md 로 옮기고 여기서 지운다. 남은 범위가 있으면 그 부분만 남긴다. 같은 일이 다시 나오면 새 항목을 만들지 않고 기존 항목을 고친다.
  - 상세 근거는 각 항목의 "참고 사항"에 연결한 기능 기록에 있다.
  - **문서 구조** : 작업 상태는 이 문서와 [completed-work.md](completed-work.md) 에서만 관리한다. 완료된 작업의 상세 기록은 `completed/`, 진행 중 작업의 상세 설계는 필요할 때만 `ongoing/`(지금은 없음), 상태와 무관한 기술 기준·결정 기록은 `reference/` 에 둔다. `completed/` 에 기록이 있어도 그 기능의 후속이 모두 끝난 것은 아니다 — 이 문서에서 확인한다. 상세 설계가 필요한 작업만 `ongoing/` 에 문서를 만들고, 끝나면 `completed/` 로 옮기며 링크를 함께 고친다. 상태 보고만을 위한 문서는 만들지 않는다.
- **상태 값** : 미착수 · 진행 중 · 부분 완료 · 검증 필요 · 결정 필요 · 보류
- **최종 갱신일** : 2026-11-16

### [AI-5-EVAL] AI 설명 업무 정확성 평가 (AI-5 남은 범위)

- 상태: 검증 필요 (실증 대기 — 실제 레거시 원본 DB·사용 승인·사람 판정자가 있어야 진행, 완료로 보지 않는다) · 우선순위: P1 · 관련 기능: AI · 선행 작업: 없음 (평가 기능은 구현됨)
- 현재 상태 : 평가 대상·사람이 확인한 실제 의미·판정 저장과 판정 기반 지표는 구현됐다. 2026-11-15 평가 화면의 테이블 고르기 500개 제한을 없앴고(쪽 목록 검색), 실제 모델 `gemma4:e4b` 로 예제 20개 대상의 **작업자(AI 코딩 도우미) 예비 평가**를 했다(맞음 9·일부 11·틀림 1 / 21, 상세 [21장](completed/ai-dictionary-draft-ai5.md)) — completed-work.md [AI-5-EVAL]. **사람이 판정한 데이터는 여전히 0건**이고 목표치가 없다. 그래서 AI-5 전체 상태는 "일부 완료" 다. 2026-11-16 실제 평가 전 신뢰성 보완을 마쳤다(판정 뒤 실제 의미·확인 상태 고정, 실제 의미 확인 전 AI 제안 블라인드, 판정 기본값 제거, 평가 대상 제안의 평가 완료 전 승인 금지, 예제 6개 대상 E2E — 테스트용 고정 판정이라 지표로 쓰지 않음, completed-work.md [AI-5-EVAL] 평가 신뢰성 보완, [23장](completed/ai-dictionary-draft-ai5.md)). 같은 날 2차 보완 : 일반 제안 화면·API 도 블라인드, 평가 대상 등록·승인 동시성(모델 대상 행 잠금), '근거 없는 주장' 필수 선택, 기존 평가 데이터 호환 확인(개발 DB 0건), 평가·일반 검토 화면 브라우저 확인 ([24장](completed/ai-dictionary-draft-ai5.md)).
- 남은 작업 : 실제 레거시 일부 테이블을 기준 데이터로 정하고, 사람이 실제 의미를 확정한 뒤 제안마다 판정을 쌓는다. 지표(정확성·근거 없는 주장·허구 객체·추천 적절성·불확실성 처리·수정률·승인율)를 보고 목표치를 정한다 (U-20).
- 남은 작업 (2026-11-16 2차 보완 뒤) : 모델·프롬프트 비교 동안 평가용 프로젝트의 메타데이터를 바꾸지 않는 운영 절차를 정하고 지킨다(`sameMetadata` 판정은 그대로). 평가 화면의 영어·다크·390·606px 확인은 2026-11-16 [AI-5-UI] 에서 끝났다(completed-work.md). 후속 검토 : 평가 대상 저장 직후 응답의 확인 시각은 메모리 값(OS 시계 정밀도)이고 다시 읽으면 DB 값(`timestamp(6)`)이라 마이크로초 아래 자리가 다를 수 있다 — 서비스 시각 처리는 바꾸지 않았고 테스트만 1마이크로초 미만 차이로 비교한다. 결정 필요 : 실제 레거시 평가 대상·규모·판정자(다중 판정자 여부), 목표치(DEC-02), 판정 변경 이력(DEC-27 — 1차 지시서의 결정 번호 D9, 로드맵 D-09 와 다름), 블라인드 중인 평가 대상 제안의 반려·보류·종결을 막을지(지금은 허용 — 내용을 보지 않고 처리할 수 있다), 확인 불가 대상의 제안은 계속 가려져 승인도 못 하는데 이를 어떻게 끝낼지(평가 대상은 판정이 없으면 지울 수 있다), 예전 규칙 데이터(미확인 대상의 판정)가 생기면 정리 정책 (이 셋은 DEC-29).
- 실제 레거시 PoC 준비 (2026-11-16, 분석·운영 절차만 — [25장](completed/ai-dictionary-draft-ai5.md)) : 기존 구현으로 진행할 수 있다(추가 구현 없이). 원본은 **PostgreSQL 12 이상만** 수집·가져오기가 되고, 원본 접속은 읽기 전용이다. 개발 DB 에는 원본 연결·SEC-1 규칙·AI 제공자가 없어 실제 원본 연결·생성은 하지 않았다. `sameMetadata` 는 대상 자신의 버전만 비교한다 — 같은 테이블 다른 컬럼·관계·표준 사전 변경과 다른 컬럼의 업무 설명 승인은 잡지 못하므로, 평가 기간에는 평가 전용 프로젝트에서 모델·표준 사전 수정·재수집·**AI 제안 승인**·업무 설명 입력을 하지 않는 운영 규칙으로 지킨다(시작·종료 모델 버전으로 확인). 결정 필요 (DEC-28) : 평가 원본(DB·스키마)과 사용 승인·읽기 전용 계정, 평가 전용 프로젝트 생성, 원본 COMMENT 를 가져올지(가져오지 않으면 모든 대상이 COMMENT 없음), 표준 사전을 구성할지(새 프로젝트는 사전이 비어 표준 범주를 못 넣는다), 비교할 두 번째 모델(로컬에는 `gemma4:e4b` 하나), 최종 규모, 판정 후 제안 처리(승인하지 않음 권장). 입력 맥락 전체 일치를 기능으로 볼지(`sameMetadata` 범위 확대)는 DEC-29. PostgreSQL 밖 원본은 [AI-2]·DEC-15.
- 완료 조건 : 합의한 규모의 판정 데이터가 쌓이고, 지표와 목표치가 기록된다. AI 판정이나 AI 확실성을 정확성으로 쓰지 않는다.
- 참고 사항 : [ai-dictionary-draft-ai5.md 16·21장](completed/ai-dictionary-draft-ai5.md), 평가 지표·기준을 바꾸는 일은 이 항목에서 사용자와 정한다. 예비 평가의 실제 의미(소스 코드 출처 포함)는 21장 표에 있어 사람이 확인할 때 출발점으로 쓸 수 있다 — 작업자 판정은 지표로 쓰지 않는다. 평가 후보 API(`/evaluation/candidates?tableId=`)는 등록 여부·제안 수를 위해 프로젝트의 평가 대상·제안 전체를 읽는다 — 제안이 많은 프로젝트에서 성능 확인 필요 (측정 데이터에는 제안이 없었다). 예비 평가로 찾은 개선 후보는 [AI-5-QUAL].

### [M-4] 역공학 연계의 남은 범위 (M-4a~M-4g 이후)

- 상태: 부분 완료 · 우선순위: P1 · 관련 기능: 원본 DB · 데이터 모델링
- 현재 상태 : 관리 화면·원본 ERD·매핑·비교·가져오기·재가져오기 구현. PostgreSQL 원본만.
- 남은 작업
  - 정책이 필요한 기능 : 원본 삭제 동기화(원본에서 없어진 객체를 모델에서 지우기), 기존 제약조건·인덱스의 구성·식 변경 교체(삭제 후 재생성), 이름 변경 후보 확정 저장(컬럼·제약·인덱스 영속 세부 매핑), 승인된 TABLE·컬럼의 원본 COMMENT 갱신 허용 여부, 원본 COMMENT 를 지우는 명시적 선택 → 7장 결정.
  - 모델 확장 : 기존 컬럼의 IDENTITY 변경 가져오기(지금 `NO_FIELD`), 생성 컬럼(`GENERATED ALWAYS AS … STORED`) 지원, 컬럼 순서 가져오기.
  - 다른 DBMS 의 비교 규칙(지금 `PostgresCompareRules` 만), VIEW 가져오기(원본 VIEW 정의 수집 이후).
  - 성능 : 3,000 TABLE 비교 조회의 1회 3초 튐 원인 분석, 비교 요청당 할당 약 468MB 줄이기(버전 JSON 한 번만 읽기 또는 읽기 캐시), M-4c 매핑 상태 이중 계산 최적화, 큰 스키마 TABLE 목록의 쪽 단위 조회.
  - 테스트 : 재가져오기 전용 동시성·기준값 테스트, 기준 연결 복귀 시 재판정, 수천 TABLE 매핑 성능.
  - 화면 : 수집 실패 시 코드별 안내 문구, PARTIAL 수집의 원본 스키마 목록 API, 수집 완료 알림, 원본 ERD 배치 저장·응답 압축, 매핑 변경 이력(지금은 감사 컬럼과 반영 순서만).
- 완료 조건 (로드맵 M-4) : 원본 연결 없이 수집 결과로 물리 모델·ERD 를 만들 수 있고, 재가져오기에서 사용자 데이터가 보존되며, 미등록 항목이 식별된다. 위 항목은 각각 사용자와 범위를 정해 나눠 진행한다.

### [AI-5-QUAL] 예비 평가로 찾은 AI 설명 품질 개선 후보

- 상태: 부분 완료 · 우선순위: P2 (임시) · 관련 기능: AI · 선행 작업: 없음 (사람 판정[AI-5-EVAL] 뒤에 하는 편이 근거가 단단하다)

- 남은 작업 (AI-5-QUAL-2, 어느 것을 할지 사용자와 정한다) : ① VERIFIED 의 의미·신뢰성(근거 객체 존재만 확인 — 이름·용어 정의뿐인 설명도 VERIFIED) ② 프롬프트 — 컬럼 설명(`description`, DDL COMMENT)과 원본 COMMENT(`sourceComment`) 구분을 맥락·규칙에 명시, 정의 복사 금지(규칙 11) 강화(`PROMPT_VERSION` 올림) ③ 응답 검증 — 정의와 같은 설명 표시·재시도, 설명이 원본 COMMENT 를 언급했는데 대상에 원본 COMMENT 가 없으면 거절, 이름·정의뿐이면 확실성 상한 INFERRED ④ 이름만 보고 만든 업무 의미 ⑤ 화면 — 평가 대상 상세에 근거 목록 표시 ⑥ 근거 데이터 — 예제 `실행_상태_코드` 정의("생성·실행 중·완료·실패·취소")가 AI 대량 생성 상태(PENDING·RUNNING·COMPLETED·PARTIAL_FAILED·FAILED·INTERRUPTED)와 다르다(원본 수집 실행과 함께 쓰는 용어라 이번에 바꾸지 않음, 한글 목록이라 비교 테스트 대상도 아님).
- 완료 조건 : 고른 개선을 같은 대상으로 다시 생성해 전후를 사람이 판정해 비교한다.
- 참고 사항 : 표본 20개·모델 1개·판정자 1명(작업자)이라 일반화할 수 없다. 프롬프트·승인 안전성 정책 변경은 이 항목에서 따로 정한다. 하위 작업(QUAL-1·QUAL-2)은 이 항목 하나로 센다.

- 현재 상태 : MCP 코드·의존성·테이블은 없다. 기존 [U-07] 은 **원본 DB 수집용 MCP Connector**(Lexorma 가 MCP 클라이언트, JDBC 를 대체하지 않는 선택 Connector)이고, 이 항목은 반대 방향 — **외부 AI 도구(MCP 클라이언트)가 Lexorma 의 메타데이터를 읽는 것**이다. 둘은 다른 작업이다.
- 지켜야 할 기존 원칙 : 단일 서버(별도 MCP 서버 프로세스를 요구하지 않는다 — [source-tool-architecture.md](reference/source-tool-architecture.md) 원칙 1·6), 원본 DB 도구는 AI 에 공개하지 않는다(AI 로드맵 원칙 12), 프로젝트 범위는 검증된 실행 컨텍스트에서만(`ExecutionContextVerifier`, 도구 인수로 받지 않음), 읽기 전용(쓰기·승인 도구 없음), 요청 로그 본문 보호(`LogBodyPolicy`), AI 없이도 핵심 기능 동작.
- 결정 필요 : DEC-31 (인증 방식·전송 방식·공개 도구 범위·프로젝트 선택·감사·켜고 끄기). 결정 전에는 구현하지 않는다.
- 완료 조건 : 정한 인증·전송으로 외부 MCP 클라이언트가 허용된 읽기 전용 도구만 프로젝트 범위 안에서 부르고, 기존 AI-4 의 권한·재검증·감사 규칙을 그대로 지킨다.
