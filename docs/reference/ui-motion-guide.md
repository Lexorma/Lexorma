# UI 모션 가이드 (UI-1, 2026-11-19 · 토스트 UI-1 후속)

업무용 데이터 모델링 도구에 맞게 **빠르고 일관된 전환과 조작 피드백**만 둔다. 화려한 효과·업무 처리를 늦추는 모션은 쓰지 않는다. 상태 기록은 `docs/completed-work.md` [UI-1]·[UI-1 후속].

## 1. 원칙

- CSS(transition·animation)를 먼저 쓴다. 자바스크립트 모션은 숫자 세기(`hooks/useCountUp`)·화면 들어올 때(`AppLayout`, Web Animations)·React Flow 화면 이동(`duration`)뿐. 애니메이션 라이브러리를 더하지 않는다 (Motion·GSAP 없음, CDN·외부 파일 없음).
- `transform`·`opacity`(그리고 독립 속성 `translate`·`scale`)만 움직인다. 레이아웃이 바뀌는 모션은 사이드바 폭·하위 메뉴 높이(grid 행) 두 가지뿐이고 짧다. `transition: all`·상시 `will-change`·무한 장식 애니메이션을 쓰지 않는다 (무한은 스켈레톤과 처리 중 아이콘 — 보이는 동안만).
- 업무 값·상태가 먼저다 : 실제 서버 응답 전에 성공을 보이지 않고, 가짜 진행률·인위적 대기·최소 로딩 시간이 없다. 모션이 끝나기를 기다리지 않고 바로 읽고 누를 수 있다.
- 다시 그리기·검색·정렬·페이지·쿼리 변경·테마·언어·창 크기에는 등장 모션을 반복하지 않는다.
- 줄인 모션(`prefers-reduced-motion: reduce`) : 장식 모션은 모두 끄고 최종 상태를 바로 보인다. 처리 중 아이콘만 느리게 남긴다. 전역 `*` 선택자로 지우지 않는다 — 각 규칙 옆이나 `motion.css` 끝 절에서 그 규칙만 끈다.

## 2. 토큰 (`lexorma-web/src/styles/motion.css`, `main.tsx` 에서 마지막에 불러온다)

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--motion-duration-instant` | 80ms | 누름(버튼 1px) |
| `--motion-duration-fast` | 120ms | 색 전환(버튼·탭·라벨·메뉴), 대화상자 닫힘, 사용자 메뉴 |
| `--motion-duration-normal` | 180ms | 컴포넌트·카드 등장, 하위 메뉴 펼침, 차트 시작 지연 |
| `--motion-duration-slow` | 240ms | 대화상자 열림·배경, 모바일 서랍, 사이드바 폭 |
| `--motion-duration-chart` | 500ms | 차트 처음 그림·값 변경 전환 |
| `--motion-stagger` | 40ms | 순차 등장 간격 (최대 5단계 = 200ms) |
| `--motion-loading-delay` | 150ms | 스켈레톤·흐림 표시를 늦춤 (빠른 응답은 깜빡이지 않음) |
| `--motion-ease-standard` / `-enter` / `-exit` | `cubic-bezier(0.2,0,0,1)` / `(0,0,0.2,1)` / `(0.4,0,1,1)` | |

줄인 모션에서는 시간 토큰이 모두 0 이 된다. 자바스크립트는 `lib/motion.ts` 의 `prefersReducedMotion()`·`motionMs(ms)` (실행할 때마다 다시 읽는다).

## 3. 공용 keyframes·클래스

`motion-fade-in`·`motion-fade-out`·`motion-rise-in`(6px 위로)·`motion-sink-out`·`motion-slide-in-start`·`motion-highlight`(바뀐 값 배경 강조)·`motion-skeleton-pulse`·`motion-spin` — 화면마다 keyframes 를 새로 만들지 않는다.
클래스 : `.motion-fade-in`·`.motion-rise-in`·`.motion-highlight`, 스켈레톤 `.skeleton`(+`.skeleton-line`·`.skeleton-value`·`.skeleton-block`·`.skeleton-row`), 처리 중 버튼 `.is-busy` + `.motion-busy-label` + `.motion-spinner`(글자 자리를 그대로 두고 아이콘을 위에 — 버튼 폭 고정), 다시 조회 중 `.is-refreshing`/`.is-refresh-ready`.

## 4. 적용 규칙

- **대화상자** (`DialogProvider`) : 열 때 배경 흐림 + 6px 등장 240ms, 닫을 때 `data-closing` 120ms 뒤 목록에서 뺀다. 닫기 콜백은 누른 순간 한 번(모션을 기다리지 않음), 닫히는 중에는 누를 수 없고(`pointer-events`), 새 대화상자를 열면 닫히는 중인 것은 바로 뺀다. 끌기(left/top·transform)와 겹치지 않게 `translate`·`opacity` 만 쓴다. 확인·판단이 필요한 알림은 대화상자, 단순한 결과 안내는 토스트(§7).
- **사이드바** : 하위 메뉴는 grid 행 `0fr ↔ 1fr` 180ms, 닫힌 메뉴는 `visibility: hidden`(탭 이동·보조 기술에서 빠짐). 화살표 회전 180ms. 모바일 서랍은 `translate` 240ms + 배경 흐림, Esc·바깥 누르기·메뉴 고르기로 닫힘. 권한 없는 메뉴는 원래처럼 그리지 않는다.
- **화면 들어올 때** : 경로(pathname)가 바뀔 때만 본문 영역 180ms 짧은 등장. 화면 컴포넌트를 다시 만들지 않는다. 첫 로그인 확인(`/api/auth/me`) 전에는 사이드바·본문·푸터를 그리지 않는다 — 빈 본문의 푸터·사이드바 없는 본문이 밀려나는 레이아웃 이동(CLS 0.25)이 없어진다.
- **대시보드** : 블록·KPI 카드 순차 등장(마지막 시작 200ms), 숫자는 처음 보일 때만 0 → 값 500ms(끝은 정확히 서버 값, 보조 기술에는 처음부터 실제 값), 값이 바뀌면 다시 세지 않고 1.2초 배경 강조. 차트는 처음 한 번 그려지고(도넛 호·막대·누적 막대, 180ms 뒤 500ms) 값이 바뀌면 길이만 전환. 첫 조회 중에는 실제 배치와 같은 높이의 스켈레톤(KPI 5 · 상자 2 · 상자 · 큰 상자 2).
- **목록** : 처음 조회는 스켈레톤 5줄(페이지 크기와 무관), 다시 조회(검색·정렬·페이지)는 앞 행을 두고 150ms 뒤 흐리게 — 행마다 애니메이션하지 않는다. 조회 실패는 '목록을 불러오지 못했습니다.' (빈 목록으로 보이지 않게).
- **버튼·탭·라벨** : 색 120ms, 누를 때 1px. 비활성 버튼은 움직이지 않는다. 승인 상태는 글자·점 표시가 그대로라 색 전환만 더했다.
- **로그인** : 상자 180ms 등장, 서버 확인·로그인 요청 동안만 버튼 처리 중(중복 요청·Enter 막음), 프로젝트 목록 앞 5개까지 순차.
- **ERD** : 노드 등장·관계선 흐름·위치 전환을 하지 않는다 (끌기·자동 배치는 즉시). 기존 화면 이동(엔터티로 이동·전체 보기 300ms)만 줄인 모션에서 0, 선택한 관계선 색·굵기 120ms, 엔터티 찾기 목록 등장.

## 5. 쓰지 않는 것

대량 표의 행별 등장, 관계선 연속 흐름, 드래그 중 위치 전환, 전체 그래프 순차 등장, 자동 배치 위치 애니메이션(노드 300개에서 위치 전환은 좌표·관계선·저장과 얽히고 비용이 큼 — 필요하면 별도 검토), 반복 확대·흔들림·Parallax·Bounce, 테마 전환 전체 화면 모션, 사용자별 모션 설정(운영체제 설정만 따른다).

## 6. 새 화면에서

토큰과 공용 클래스를 쓴다. 등장 모션이 필요하면 `.motion-rise-in`, 첫 조회는 실제 모양의 `.skeleton`, 처리 중 버튼은 `.is-busy` 묶음, 숫자는 `CountUp`(대시보드 `charts.tsx`)·`useCountUp`. 지연 로딩되는 화면 CSS(예 `erd.css`)에서는 토큰을 쓰고 그 파일에 줄인 모션 절을 함께 둔다. 새 모션은 줄인 모션을 함께 정의하고, 큰 목록·ERD 에는 붙이지 않는다.

## 7. 토스트 (UI-1 후속, `components/toast/ToastProvider.tsx`·`toastStore.ts`, `styles/toast.css`)

### 7.1 토스트와 대화상자

| 상황 | 쓰는 것 |
|---|---|
| 서버가 성공을 돌려준 단순 결과 (등록·수정·삭제·승인·승인취소·매핑·매핑 해제·순서 저장·복사 완료·한 번의 일괄 처리 요약) | 성공 토스트 |
| 확인이 필요 없는 짧은 안내 ("변경 요청을 만들었습니다. 승인되면 반영됩니다.", "같은 표준 용어라 바꾸지 않았습니다.") | 안내 토스트 |
| 삭제·승인·매핑 해제·미저장 변경 확인, 업무 제약 안내 (예 : 속성 매핑이 있어 해제 불가) | 기존 확인·알림 대화상자 |
| 입력 검증 실패 | 기존 필드 표시 또는 알림 대화상자 |
| 서버 오류·HTTP 409 충돌·권한 오류 (공통 오류 처리 `ApiErrorBridge`) | 기존 알림 대화상자 — 오류를 토스트로 바꾸지 않는다 |
| 세션 만료·중복 로그인·프로젝트 접근 상실 | 기존 안내 대화상자 (뜨는 순간 토스트는 모두 지운다) |
| 여러 건의 성공·실패·건너뜀이 섞인 결과, 상세 결과 (엑셀 업로드, 모델 가져오기, 물리 모델 생성, 원본 삭제 반영, AI 화면의 처리 결과) | 기존 결과 대화상자·화면 안 표시 |
| 오류·경고 토스트 | 인터페이스만 있다 (지금 쓰는 곳 없음). 실제로 비차단 알림이 필요한 기능에서만 — 짧은 문장으로 이해되고, 사라져도 화면에서 상태를 확인할 수 있는 복구 가능한 오류·경고에만 쓴다 (2026-11-19 결정) |
| 물리·논리 ERD 배치 저장 결과 | 기존 화면 안 안내 그대로 (토스트로 바꾸면 같은 결과를 두 번 알림, 2026-11-19 결정) |

### 7.2 쓰는 법

```tsx
const toast = useToast();
const response = await api<{ result: boolean }>('/api/…', { method: 'PUT', body });
if (!response.result) return;
reload();                                   // 후속 처리 먼저 (목록 다시 조회·폼 닫기·상세 다시 열기)
toast.success(t('정상적으로 저장되었습니다.')); // 그 다음 안내 — 토스트가 닫히기를 기다리는 일은 없다
```

- `toast.success|info|warning|error(message, { title?, duration?, dedupeKey? })`, `dismiss(id)`. `clear()` 는 공통 처리(세션 만료)만 쓴다 — 화면이 다른 화면의 알림을 지우지 않는다.
- 문장은 기존 번역 키를 그대로 쓴다 (`t('…')`). 내용은 글자로만 그린다 (HTML·JSX·버튼·되돌리기 없음, `dangerouslySetInnerHTML` 없음). 서버 오류 원문·비밀값·블라인드 평가 내용은 넣지 않는다.
- 서버 응답으로 성공을 확인한 뒤에만 부른다. 같은 결과에 토스트 한 번 (공통 오류 알림과 화면이 둘 다 알리지 않는다). 여러 행을 한 번에 처리해도 요약 하나.

### 7.3 동작

| 항목 | 값 |
|---|---|
| 자리 | 데스크톱 오른쪽 아래 (오른쪽 76px — AI 도우미 버튼 왼쪽, 아래 24px, 폭 최대 400px). 모바일(< 768px) 좌우 16px · 아래 76px(+ safe area), AI 도우미 버튼이 푸터 때문에 올라가면 그만큼 같이 올라간다(`--ai-assistant-lift`, `AiAssistant` 가 `:root` 에 둔다 — 버튼과 12~20px 간격, 세로 탭일 때는 그대로). AI 도우미 창이 열리면 오른쪽 위 76px, 대화상자가 열려 있으면 위 16px |
| 레이어 | 목록은 `popover="manual"`(최상위 레이어) — 열린 대화상자 위에도 보이지만 대화상자가 열린 동안은 inert(포커스·클릭·보조 기술에서 빠지고 누르면 아래 대화상자로 간다). 새 토스트가 보일 때 대화상자가 열려 있으면 위로 다시 올린다. popover 미지원 브라우저는 fixed + z-index 45 (대화상자가 열려 있으면 그 배경 아래라 보이지 않고, 안내는 live region 으로만). 목록의 `display: flex` 가 기본 숨김을 이기므로 닫힌 popover·`hidden` 은 `toast.css` 에서 다시 `display: none` |
| 동시 표시 | 3개. 넘치면 대기열(최대 10, 차면 가장 오래된 성공·안내부터 버림 — 오류·경고는 성공·안내가 없을 때만) |
| 표시 시간 | 성공 3초 · 안내 4초 · 경고 5초 · 오류 6초, 긴 문장은 글자당 60ms 까지 늘림(최대 10초). 화면에 보인 때부터 센다 (대기 중에는 줄지 않음) |
| 일시정지 | 마우스가 위에 있을 때·키보드 포커스가 안에 있을 때·브라우저 탭이 가려졌을 때. 이유가 모두 풀려야 남은 시간으로 다시 센다 |
| 중복 | `dedupeKey` 가 같으면 새로 만들지 않고 시간을 처음부터 다시 센다 (다시 읽지도 않는다). 키가 없으면 문장이 같아도 따로 보인다 — 같은 문장을 돌려주는 서로 다른 업무 결과를 합치지 않는다 (예전 '1초 안 같은 문장 = 하나' 규칙은 2026-11-19 삭제) |
| 닫기 | 닫기 단추(`알림 닫기`, Enter·Space). 전역 Esc 로 닫지 않는다 (대화상자 Esc 와 겹치지 않게). 닫는 중에는 inert. 포커스가 있던 토스트를 닫으면 다음 토스트의 닫기 단추, 없으면 들어오기 전 자리로 |
| 범위 | 사용자·프로젝트·로그인 차례에 묶인다. 로그아웃·재로그인·세션 만료(안내가 뜨는 순간)·사용자 변경이면 보이는 것·사라지는 중인 것·대기열·타이머를 바로 지운다. `useToast()` 함수는 그 화면이 그려진 때의 범위를 기억해, 이전 범위에서 시작한 요청의 늦은 응답은 토스트를 만들지 못한다 (같은 사용자·프로젝트로 다시 로그인해도). 프로젝트는 로그인 때 고르므로 프로젝트 변경 = 재로그인 |
| 언어 | 언어는 화면을 열 때 정해진다(`lib/i18n`). 언어를 바꾸면 새로고침이라 토스트가 남지 않는다 — 섞인 언어가 생기지 않는다 |
| 저장 | 메모리에만 둔다 (localStorage·서버 없음). 새로고침·재로그인 뒤 다시 보이지 않는다. 서버 요청·API·WebSocket 을 더하지 않는다 |
| 보조 기술 | 늘 있는 live region 두 개 — 성공·안내·경고는 `role="status"`(polite), 오류만 `role="alert"`(assertive). 토스트 자체는 live region 이 아니다(두 번 읽지 않게). 대화상자가 열려 있으면 바깥이 모두 inert 라 영역을 맨 위 대화상자(닫는 중 제외) 안으로 옮기고, 닫는 중인 대화상자가 맨 위에 남아 있으면 빠질 때까지 기다린다 (`Announcer`). 안내마다 한 번만 넣는다 — 읽은 id 를 기억해 영역이 옮겨지거나 다시 그려져도 다시 읽지 않고, 짧은 사이에 여러 개가 보이면 120ms 간격으로 차례로 넣으며(최근 5개), 넣은 뒤 3초에 비운다. 유형은 아이콘 모양·왼쪽 띠·숨은 라벨(성공·안내·경고·오류)로 구분, 색만으로 구분하지 않는다. 포커스를 가져가지 않는다 |
| 렌더링 | 목록은 `useSyncExternalStore` 로 토스트 영역만 구독한다 — 토스트가 바뀌어도 업무 화면(그리드·ERD·대시보드)은 다시 그리지 않는다 |
| 검증 | `window.__lexormaToastStats()` 가 보이는 수·대기열 수·걸린 타이머 수만 돌려준다 (내용 없음, 브라우저 검증 스크립트용). 개발 서버(`npm run dev`)와 `vite build --mode test` 빌드에만 있고 운영 빌드에서는 코드째 빠진다 |

### 7.4 모션

등장은 `motion-rise-in`(6px, `--motion-duration-normal` 180ms, enter), 닫힘은 `motion-sink-out`(`--motion-duration-fast` 120ms, exit) 뒤 160ms 에 목록에서 뺀다. 가운데 토스트가 빠지면 나머지는 Web Animations 로 180ms 제자리 이동(FLIP, `motionMs`) — 목록 자체가 옮겨진 때(대화상자·AI 도우미 창이 열려 위로 감)는 움직이지 않는다. 줄인 모션이면 등장·닫힘·이동 없이 바로 보이고 바로 빠진다 (`motion.css` 줄인 모션 절, `toastStore` 도 기다리지 않음). 토스트는 고정 위치라 본문 레이아웃을 움직이지 않는다.

### 7.5 한계

- 대화상자가 열린 동안 생긴 토스트는 inert 라 마우스를 올려도 멈추지 않는다 (안내 문장은 대화상자 안 live region 으로 읽는다). 대화상자 안의 상태 표시는 그대로다.
- 모바일에서 AI 도우미 창은 화면 전체라(576~767px 는 오른쪽 아래 창), 그 위의 토스트는 창 위쪽 76px 아래 대화 내용 일부를 몇 초 가린다 — 창 머리(닫기)와 아래 입력칸은 가리지 않는다.
