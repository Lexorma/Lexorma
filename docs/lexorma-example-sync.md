# LEXORMA 예제 ↔ 실제 스키마 일치 (V6) · FK 규칙 · IDENTITY (V7)

2026-11-14. 프로젝트 0(LEXORMA 예제)은 Lexorma 자신의 스키마를 모델로 옮긴 것이므로, Lexorma DB 를 원본으로 수집해 비교하면 매핑된 모든 TABLE 이 **같음**이어야 한다.

## 1. 진단 (개발 DB 복사본, 비교 서비스로 집계)

처음 : 매핑 66 중 같음 40 · 다름 14 · 판단 불가 12. 원인

| 원인 | 내용 | 조치 |
|---|---|---|
| 예제 누락 | FK 23 (`TB_SRC_*`, 복합 9 포함), UNIQUE 3, CHECK 2, `MPNG_EXCL_YN` 기본값 | V6 |
| 비교 규칙 | 모델 `BIGINT ARRAY` ↔ 원본 `bigint[]` 를 같은 타입으로 보지 못함 | `PostgresCompareRules.type` 수정 |
| 모델 칸 없음 | FK 13개의 `ON DELETE CASCADE`·`SET NULL` (판단 불가) | V7 FK 규칙 |
| 모델 칸 없음 | `TB_LOG.LOG_SN` `GENERATED BY DEFAULT AS IDENTITY` | V7 IDENTITY |

결과 : 같음 64, 나머지 2 는 V7 의 새 컬럼이 원본 카탈로그에 아직 없어서다 (원본을 다시 수집하면 같음). FK 규칙·IDENTITY 차이는 없어졌다.

**어긋난 이유** : 초기 데이터 검사가 TABLE·컬럼·COMMENT 만 실제 스키마와 대조했다. 이제 `V0SeedMigrationTest` 가 FK·UNIQUE·CHECK 이름, 기본값이 있는 컬럼, FK 삭제·수정 규칙, IDENTITY 까지 대조한다 (H2·PostgreSQL). 테이블·컬럼·제약을 더할 때 같은 마이그레이션에서 예제도 맞춰야 통과한다.

## 2. V6 `V6__lexorma_example_sync.sql`

- FK 는 실제 제약 이름 그대로 관계(출처 `USER`, 승인)로 넣는다. 참조 컬럼(`REF_COLUMN`) 관계는 앱의 참조 동기화가 이름을 `FK_<테이블>_<컬럼>` 으로 다시 지어 실제 이름과 달라지므로 쓰지 않았다.
- FK 마다 논리 관계도 넣는다 (V1 규칙 : 상위 → 하위, 이름 = 상위 엔터티명, FK 컬럼이 모두 PK 면 식별, NULL 허용이 있으면 상위 최소 0).
- 같은 이름이 이미 있으면 건너뛴다 (가져오기 등으로 먼저 넣은 설치). 기존 데이터를 지우거나 바꾸지 않는다 (기본값 1개는 비어 있을 때만 채운다).

## 3. V7 `V7__relation_rules_identity.sql` — 모델 속성 두 가지

| 속성 | 저장 | 값 | DDL |
|---|---|---|---|
| FK 삭제·수정 규칙 | `TB_TBL_REL.DEL_RULE_CD` · `MDFCN_RULE_CD` (`TableRelation.deleteRule`·`updateRule`) | NO_ACTION · RESTRICT · CASCADE · SET_NULL · SET_DEFAULT, 비면 NO ACTION | `ON DELETE …` · `ON UPDATE …`. NO ACTION 은 쓰지 않는다 (기존 DDL 그대로). Oracle 은 ON DELETE CASCADE·SET NULL 만, MySQL·MariaDB 는 SET DEFAULT 없음 → 빼고 경고 |
| IDENTITY | `TB_COL.AUTO_CRT_MTHD_CD` (`ColumnInfo.identity`) | ALWAYS · BY_DEFAULT, 비면 없음 | PostgreSQL·Oracle `GENERATED … AS IDENTITY`, MySQL·MariaDB `AUTO_INCREMENT` (ALWAYS 는 경고). 기본값과 함께 있으면 기본값을 빼고 경고 |

- **저장·검증** : 관계 등록에 규칙을 받고, 규칙만 바꾸는 `PUT /api/physical/relation/{id}/rules` (USER, 참조 컬럼 관계 포함, 승인된 관계는 거절, 논리 관계는 거절). 참조 동기화는 관계를 고칠 때 규칙을 유지한다. IDENTITY 는 정수 타입(SMALLINT·INTEGER·BIGINT, 소수 없는 NUMBER·NUMERIC·DECIMAL)에만, 기본값과 함께 쓰지 않는다 (컬럼 등록·일괄 저장 검증).
- **변경 이력·모델 버전** : `ModelChangeRecorder` 필드 목록에 `deleteRule`·`updateRule`·`identity` 추가.
- **비교 (M-4d)** : FK 규칙을 모델 관계의 규칙과 비교한다 (판단 불가 → 같음·다름). 자동 증가는 모델 IDENTITY 를 먼저 보고, 예전처럼 기본값 칸의 `GENERATED … AS IDENTITY` 문구도 읽는다.
- **가져오기 (M-4e·M-4f)** : 새 FK 에 규칙을, 새 컬럼에 IDENTITY 를 그대로 가져온다 (이전에는 만들지 않았다). 기존 컬럼의 IDENTITY 변경은 아직 가져오지 않는다 (`NO_FIELD`, 후속).
- **화면** : 물리 ERD 관계 등록에 규칙 선택, 관계 패널에서 규칙 표시·변경(편집 모드, 미승인), 컬럼 등록·일괄 편집에 IDENTITY 선택, 변경 이력의 필드 이름.
- **예제** : 용어(삭제_규칙_코드·수정_규칙_코드는 원본 카탈로그 테이블의 것을 재사용, 자동_생성_방법_코드 추가)·물리·논리·매핑, FK 13개 규칙, `TB_LOG.LOG_SN` BY_DEFAULT.
